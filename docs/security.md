# Security

The agent exposes read-only health and clipboard progress queries over native local IPC. The health response contains the process ID and uptime in whole seconds. The clipboard progress response contains connection and transfer states.

- Windows names its pipe using the logon SID, sets an explicit DACL for that SID, and rejects remote clients. The CLI opens the pipe at identification-only impersonation level and checks that the pipe owner matches its user SID before sending a request. First-instance creation prevents concurrent agents on the same endpoint. Other accounts guessing and precreating a pipe name can cause denial of service. The owner check rejects a forged response from such an account. [Microsoft named pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)
- Linux and macOS use a socket in a user-owned mode-0700 directory. Both endpoints compare effective user IDs using native peer credentials. A lock serializes binding, stale socket removal, and shutdown cleanup. The fallback under `/tmp` can be precreated by another local user, resulting in a startup failure. The ownership check fails closed. [Tokio peer credential implementation](https://docs.rs/tokio/latest/src/tokio/net/unix/ucred.rs.html)
- The agent bounds each exchange by time and frame size. A stalled local client can delay other local requests for up to one exchange deadline per connection. Processes with the same user or logon rights and OS administrators are inside the local trust boundary.

The optional browser monitor runs in the CLI on an ephemeral IPv4 loopback port. Its private URL uses a random 128-bit token and the server checks the loopback Host header. It serves a static page and read-only clipboard states without clipboard contents, peer identities, or shared configuration. Responses prohibit caching and referrer forwarding.

## Manual peer trust

The opt-in QUIC endpoint uses TLS 1.3 and requires client certificates. Each configured SHA-256 fingerprint must match the imported public certificate. Rustls validates outgoing connections against the intended peer and incoming connections against the configured trust set. The application requires an exact match of the presented leaf before exchanging readiness frames. TLS resumption is disabled so a reconnect presents certificates again. In manual-only mode, an incoming connection must use the configured source IP for that peer. Discovery mode permits a trusted peer's source IP to change and continues to require address validation and certificate authentication. One incoming session slot per peer and a separate limit of eight concurrent incoming handshakes keep connection handling bounded.

mDNS publishes the certificate fingerprint and listening endpoint on the selected LAN interface. Advertisements supply address hints for fingerprints in the local config. A spoofed hint can cause failed connection attempts, with retries governed by the transport's backoff. A successful session still requires proof of possession of the pinned private key.

Installation identities use self-signed Ed25519 certificates. The device ID is the first 128 bits of the certificate digest. Trust uses the entire SHA-256 fingerprint. Windows protects the private identity file using current-user DPAPI. macOS and Linux use an owned file with mode 0600 or stricter. macOS Keychain and Linux Secret Service integration are future work. Use a directory that only the account owner can modify.

## LAN requirements for later phases

Input control is disabled unless the local config explicitly selects a mode and a pinned peer fingerprint in `[input]`. Each receiver checks local focus and desktop access before granting an input session on the selected authenticated connection. Physical activity on the receiver revokes the grant. Each native backend filters its own synthetic events to prevent feedback. Fixed frames, a bounded capture queue, and a renewable lease limit the input session. Logs record session lifecycle and errors without recording input events.

`input.allow_locked_receive` is a separate opt-in. On macOS, it permits reception on this user's already logged-in, active console session while normally locked; it does not permit sending protected local input or receiving into unrelated Secure Input fields. Missing or malformed session identity, console, or login state denies reception. Local keyboard takeover cannot be guaranteed while the OS withholds protected events; the unlocked sender's emergency shortcut and the existing lease remain active. Windows locked reception remains unsupported without a separate authenticated privileged injector. The standalone Windows capability probe never injects input or receives network data.

Clipboard sync requires a separate `[clipboard]` opt-in for one pinned peer on both machines. Peers exchange a versioned readiness record over the authenticated connection before sharing any clipboard contents. Each session starts from the current clipboard sequence without sending existing content. The agent skips supported privacy markers and protected desktop sessions. Unmarked sensitive content can still be shared. Incoming updates must have the selected peer's origin and a newer revision. Native writes refuse a changed sequence when the platform can detect it, and mark imported entries to suppress retransmission. Plain text and optional HTML are each bounded to 64 KiB. Image updates are bounded to 8 MiB of encoded PNG and checked against both pixel dimensions and decoded size before a native write. Clipboard data stays out of logs and agent storage. UniKVM passes HTML to the native clipboard as data. The destination app controls how it interprets that data when pasted.

Treat mDNS, IP addresses, hostnames, and advertised IDs as untrusted hints. Pairing requires explicit approval and verification of both peer identities using a reviewed certificate fingerprint workflow or vetted PAKE. Bind a persistent random device ID to the verified certificate identity. Reconnect only against pinned trust and support revocation. Give input, clipboard, and file receipt separate permissions.

Use reliable streams for key and button state and bound every message, stream, and queue. Leases and disconnect paths must restore local control and release held synthetic state. Logs may contain operational state and counts. Keep key data, clipboard contents, and secrets out of logs.

Stream approved files to a bounded staging area. Validate filenames and destination paths, defend against traversal and symlink escape, check content integrity, and publish without silently overwriting a file.
